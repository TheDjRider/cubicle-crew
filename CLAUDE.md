# Cubicle Crew (formerly Pixel Office) – notes for Claude

Local app that shows Claude Code sessions as pixel-art people in an office. Node server tails
`~/.claude/projects/**/*.jsonl` and pushes events over WebSocket; a vanilla-JS canvas client renders them.
Ships as a browser app (`npm start`) and as an Electron desktop widget with a Windows installer.
User-facing docs: `README.md` (English, GitHub landing page; media in `docs/media/`) + translations `README.ja.md` / `README.zh-CN.md` (they say the English one is the latest; update them for big features, the Settings section only links to the English list). Gamification (`docs/gamification.md`): phases 1–4 done – tokens, decor, shop, achievements.

## Commands
```bash
npm start                 # server + web UI on http://localhost:4317  (PORT=, CLAUDE_PROJECTS_DIR=)
npm run debug             # same, logs every parsed event and how sub-agent parents were resolved
npm run desktop           # Electron widget (runs its own server; 4317 busy -> 4318..4320 -> random)
npm run dist              # Windows NSIS installer -> release/CubicleCrew-Setup-<version>.exe (bump "version" first; predist wipes release/)
npm run icon              # regenerate build/icon.png + icon.ico from electron/icon-art.js (32x32 art for big sizes, 16x16 for 16/48 px + tray; no deps)
node scripts/shot.cjs "<url>" <outPrefix> <w> <h> <dpr> <ms,ms,...> [evalJs] [preEvalJs]
                          # headless Chrome screenshots + console errors + external requests (see Testing)
```
There is no build step for the client and no test framework. `node --check <file>` for syntax.

## Hard constraints (from the user, keep them)
- **No external assets/CDN/fonts, works offline, no client build step** (plain ES modules in `public/`). The only network calls are the opt-in weather (server-side, only after the user picks a city) and the opt-in update check – the page itself never talks to the internet.
- **WebSocket protocol:** only ever *add optional* fields. Event: `{agent, label, subagent, ts, type: tool_start|tool_end|say|user_prompt, id, tool, detail, tool_use_id}` + optional `parent, parent_tool_use_id, background, desc, link, model` (raw model id; the client shortens it with `shortModel()` in `util.js` – trailing `-YYYYMMDD` cut – and shows a `T.model` row in card + tooltip only when known; Claude assistant lines, OpenCode `modelID`, Codex `token_count.info.model` if present; Gemini has none; the OpenCode live list and `presence` carry it too).
- **State colours are the visual language:** idle `#6b6b80`, thinking `#e0c24a`, typing `#4ac26b`, reading `#4a8fe0`, running `#e07a4a`, delegating `#b04ae0`, waiting `#e04a6b` (`STATES` in `public/config.js`).
- **UI is bilingual:** `T_BG` / `T_EN` in `config.js` (`T` = the active one, `LANG`, `setLang()`, `itemName(it)` for shop items – `catalog.js` keeps the Bulgarian names, English ones are in `T_EN.items`). Language: `?lang=en|bg` → saved `localStorage po.lang` → system language (`bg*` → bg, else en); HUD chip БГ/EN; Electron: tray submenu "Language", `settings.lang`, passes `&lang=` to the page (the HUD chip in the app sends `action("lang:xx")`). **Every new UI string goes into both.** Code comments in this repo are Bulgarian – match it.
- **All text is DOM** over the canvas (crisp, Cyrillic). The 3x5 `pixelfont.js` is only for digits/symbols inside the scene.
- **Integer pixel scaling** in *device* pixels: canvas is logical size (e.g. 640×360), CSS size = W*scale/dpr.
- Keep `?demo` and `?demo=showcase` working; they are how features get checked without real sessions.
- The procedural art must stay **override-able** by PNGs (`public/sprites/characters.png`, `tiles.png`+`tiles.json`); new props should go through `prop(name, …)` in `environment.js` so a tileset can replace them.

## Release announcements
After the user ships a new version (`gh release create v…`), or mentions a new tag or release, ask whether to run the
`release-announcer` skill (`.claude/skills/release-announcer/`) – never start it on your own. A PostToolUse hook
(`.claude/hooks/release-check.mjs`) adds the same reminder after release commands. Drafts go to `release-posts/` (gitignored).

## Architecture (public/)
- `config.js` – `CFG` constants, `STATES`, `T` strings (`T_BG`/`T_EN`), URL `PARAMS` (`demo, debug, agents, time, wander, seed, desktop, web`…); re-exports `TOOL_STATE`/`DELEGATE_TOOLS` from `rules.js`.
- `rules.js` – **shared with the server** (no DOM/`location`!): `TOOL_STATE`, `EARN` weights/bonuses, `Earner` (events → whole tokens per agent + bonuses).
- `tokens.js` – client wallet: HUD chip, whiteboard plaque (`office.tokens`), `+N` particles (≤1 per agent / 20 s, bonuses immediate), `drawCoin`; applies `equipped` → `office.setDecor()` (or the shop's `setPreview`); `backend` = server POSTs or `demoWallet` (in-memory, 10× rate, starts with 600 / 1240, owns + wears `massage.chair` with `shop.1` pre-granted).
- `catalog.js` – **shared with the server**: `SLOTS` (slot → group + free default; `def: null` = on/off item), `ITEMS` (id, group, price, Bulgarian name, colours/style), `TABS`, `ACHIEVEMENTS`, `buyItem`/`equipItem`/`grantAchievements`, `resolveDecor(equipped)`. **Item ids are save data – never rename.** New item = one line here + (for a new style) a branch in the matching draw function in `environment.js` + thumbnail case in `thumb()`.
- `shop.js` – shop as a **tall left panel** since 2.12 (DOM, `#shop` full height, width `--shop-w` = clamp(340px, 36vw, 480px), in a small window (`max-width: 899px` or `max-height: 539px` – the same media query in `index.html` and `SMALL` in `shop.js`) clamp(220px, 46vw, 340px) with denser CSS and ~76×58 thumbnails; `body.shopping #stage` moves right of it; below 480 px wide it falls back to a bottom drawer 62vh; `body.shopping` hides HUD/legend; `shop.onToggle` -> `main.js resize()` fits the office *next to* (or above) it so the hover preview is fully visible), thumbnails (integer-scaled canvases, ~116×88), hover preview, trophies tab; opened by HUD coin or the "Магазин" bag button / B / tray+⚙ "Магазин" (`open-shop` IPC). **The Electron window never grows for the shop, settings or setup** (users asked, 2.14.1): the `shop` IPC only wakes, focuses and drops click-through (`shopOpen`, which also blocks `prefer-size`/sleep); the page fits the panels in (office next to the shop at scale 1, more scrolling).
- `model.js` – events → per-agent state (pending tools + 8 s idle rule, unchanged from v1); parent/child links; leave rules; emits `join/leave/link/state/celebrate`. No drawing.
- `office.js` – the scene: **teams & seats**, lounge queue/swap (`manageTeams`), routing on lanes, particles hooks, layered rendering, hit-testing, DOM anchor points.
- `layout.js` – room need **356×182** since 2.19 (356×208 from 2.8; `ROW_STEP` 40 = the sub row sits 40 px under the lead row, slightly overlapping; `POD_H` 66, `MARGIN_L` 12 – the door is on the wall above the top lane, its exit is `lane 'row'` at `topY`, `leftLaneX` = left of the first desk column; the whiteboard starts right of the door). Electron `TARGET` 712×364, `migrateSize()` shrinks windows still at an old default (790×470, 712×416 – `OLD_TARGETS`) once (`settings.size219`). `computeLayout(devW, devH)`: fixed plan (2 lead desks + 3 shared sub desks), picks integer scale, room fills the window up to `CFG.MAX_STRETCH` (1.6× the need per axis – at scale 1 next to the shop it used to become tiny desks on an endless floor); the rest is empty and `main.js resize()` centres `#stage` with a `transform` (not in clear mode, not vertically on a portrait phone). `POD` = geometry inside one 72×76 desk pod (seat, aisle, monitor, label…). Pods carry `{team, role:'lead'|'sub', slot}`.
- `environment.js` – room prerender (`buildRoom` → `bg` canvas + depth-sorted prop images), sky by real local time (`timeOfDay`), wall clock, whiteboard stats, door, tint (multiply) and `glow` (additive). Colours of furniture: `ENV` in `palette.js`, `SOFA`/`LEAD` consts and `RUGS` array in `environment.js` (this is where decor theming will hook in).
- `sprites.js` – 24×32 character generator from string pixel maps + palettes, auto selective outline, two layers (`body`, `front` = hands/paper drawn over the desk), cache; `POSES`/`POSE_ORDER`; PNG sheet override. A look (`lookFor(id)` – random by id, ~50% women) = `fem`, `hair` (style from `HAIR_STYLES`: map + `behind`/`strands`/`tail`/`bun`), `top` (tee/collar/tie/hoodie/vneck/stripe/blouse/scoop), `bottom` (pants/skirt/dress – a dress uses the state colour), `short` sleeves, `beard`, `earrings`, `iris`, `tights`. Shirt = state colour stays the dominant colour – keep it that way when adding clothes. Pixel-map keys are listed at the top of the file.
- `characters.js` – `Actor` (pose selection per state, walking, pacing, fades) and the pets (`Pet` → `Cat`, `Dog`).
- `life.js` (prototype "Life", `office.life`): small stories that never need attention. Icon-only chat bubbles between idle lounge agents (`chatTick`, `drawSay`, `ICONS`/`TOPICS`, wakes a dozer), team + lounge cheer on `celebrate`, click on an idle agent = wave (`office.greet` from `ui.js`), pets on errands (`Pet.errand(pts, {rest, ms, end, then, onArrive, onLeave, sleepAfter, rush})` in `characters.js`: sit by a `waiting` agent, rush to a celebrating lead, cat naps in a sunbeam / hops onto an empty desk keyboard (`jump`, `keyOverride`), dog fetches the ball to someone resting, cat follows walkers, sitting pets watch walkers), rare events (`start('bird'|'courier'|'cake')`: robin on a window sill drawn before `room.bg`, courier drops a parcel by the door, cake + candle on a lead's desk at the 100/250/500… tool call via model `tool_start` → `office.onTool`), rare bookshelf trip on WebFetch/WebSearch (`loc.type 'books'`). Sub-agents hand their result to the lead before leaving (`loc.handback`, `office.handbackTick`); thinking agents sometimes peek over a working neighbour's shoulder (`loc.type 'peek'`). Actor micro-life in `characters.js`: `FIDGETS`/`lifeTick` (random sip/stretch/yawn/phone/lean per state, staggered), `gaze` (eyes `'l'|'r'` in `sprites.js`), `react` (`hi`/`cheer`/`talk` → `hiA…`, `couch*`/`stand*` variants). Open API (`external.js`, server-side, in `build.files` and npm `files`; docs `docs/api.md`): `POST /api/event` (JSON, no foreign Origin, ≤1 MB) → `External.ingest(body, ?from, ?event)`: native `{agent, type: start|prompt|thinking|tool_start|tool_end|activity|waiting|idle|end, label, provider, tool, detail, id, reason}` or a hook payload (Copilot CLI camel/PascalCase, Cursor, Claude-style `hook_event_name`) → events via `emitEvt` (ids `<provider>:<id>`, tool names mapped by `TOOLS`, `activity` = current action until the next) + status in `external.list()`, merged into the live sessions list in `scanSessions()` (so waiting/ended work through `model.sessions`; the list carries optional `provider`). Busy → idle after 10 min, dropped after 60 min, max 40. Hooks always get `{}`. `npx cubicle-crew event <type> --agent …` posts to 4317–4320. Provider names in `PROVIDERS` (`config.js`).

## Office model (decided with the user)
- **Team = one Claude Code session** (orchestrator). **Fixed office, nothing appears or re-lays out** (decided 2026-10-15): one shared rug, top row = the two lead desks (team 1 left column, team 2 right column, printer + plant between them – `buildRoom`), below = **one row of 3 shared sub-agent desks** (`SUB_PER_ROW`; pods with `team: null`). `computeLayout(devW, devH)` has no spec; scale logic unchanged (= the old one-team size, widget stays ×2).
- **Any sub-agent sits at any free sub desk** (`freeSubSlot()` is global, seat `{role:'sub', slot}` – `podIndexOf` ignores the team for subs). No free desk → it works **with a laptop** in the lounge (`workSpot()`: sofa → `couchLaptopA/B`, else a `lounge` extra spot → `standLaptopA/B`; prop `laptopA/B`, colours `X`/`I` in `sprites.js`), and takes the next desk that frees up (`manageSubs()` in `manageTeams`, working ones first, then by `joinSeq`). 3rd+ working sessions also work on laptops in the lounge until a lead desk frees up (swap rules below unchanged).
- **Team = mug colour** on the desk: `drawMug` is no longer baked into the pod image – `drawPodFront` draws it every frame in the colour of the sitter's team (`leadOf(a)` → `seat.team` → `TEAM_MUGS` teal / magenta; lead without a desk → white; empty desk → no mug). The parent–child lines show the rest. (Emblems/flags were tried and dropped by the user.) Shop: `rug.team1` and `chair.team1` slots are `hidden` (kept for saves); `chair.team0` = sub-agent chairs.
- **Only working leads hold a desk** (asked by the user): an idle lead with no live sub-agents that is already in the lounge (`LOUNGE` loc types) releases its desk in `manageTeams`; idle queued/joining leads never take one (an idle `presence` join walks from the door to the sofa). Sofa seats are 26 px apart (`SOFA_SEATS` in `environment.js` = `lounge.spots.sofa` in `layout.js`), the 2nd sofa label is stacked one row lower (`ui.js`). Every main agent's label gets ★.
- **Max 2 teams** (`CFG.MAX_TEAMS`) at the lead desks. **Hot desks** (2.13, decided 2026-10-19): a 3rd+ working session takes a free sub-agent desk – seat `{role:'sub', slot, hot: true, team: 2..4}` (`hotSeat()`/`hotTeam()`), mug colours `TEAM_MUGS[2..4]` (lime, cocoa, indigo), ★ label as usual; released by the same idle-in-the-lounge rule; when a lead desk frees up while a sub-agent works on a laptop, the oldest working hot lead moves to the lead desk. Only with no free desk at all it works on a laptop in the lounge; an active queued session still swaps with a lead idle > `SWAP_IDLE_MS` (20 s) that has no live sub-agents. With 1–2 sessions nothing changes.
- Sub-agents enter through the door; lead walks over to hand the paper (≤ once per 10 s, else paper plane).
- Parent link priority (server): `subagents/agent-<id>.meta.json` `toolUseId` (exact) → `sessionId`/folder → 15 s heuristic. Child leaves on parent's `tool_end` for its `parent_tool_use_id`, or after 30 s quiet (3 min if last event was an unfinished tool).

## Gotchas learned the hard way
- **Security (keep it):** the server binds `127.0.0.1` only (`HOST`), every HTTP request and WebSocket upgrade passes `localReq()` (Host must be localhost/127.0.0.1/[::1], Origin absent or local – blocks other websites and DNS rebinding; browsers allow cross-origin `ws://`, so the WS check matters), bad `%`-escapes → 400, static files must be inside `PUBLIC + sep`. Transcripts created before the server started and first seen later (`claude --resume`) are read from their end, not replayed. Server-to-server calls use `http://127.0.0.1:<port>`; the Electron page keeps `http://localhost` (changing the origin wipes localStorage).
- `ws` re-emits HTTP `listen` errors as **uncaught exceptions** → `startServer` probes the port with a separate `net` socket first. Don't remove that.
- Shell heredocs mangle long Python/JS edits with quotes/`\n`; write edit scripts to a file instead.
- A random server port changes the page origin and wipes `localStorage` prefs → Electron prefers fixed 4318–4320.
- Many tool sandboxes block writes outside the project/scratch dir; Electron logs to its userData dir.
- Windows PowerShell 5 `Compress-Archive` writes backslash paths → use `tar -a -c -f x.zip`.
- To run a second Electron instance next to the user's installed app, pass `--user-data-dir=<other dir>` (single-instance lock + settings are per userData).
- Seated characters are drawn in 3 slices: chair (depth `pod.y+18`) → body (`+24`) → desk + `front` layer (`+30`). Walkers sort by feet y. New furniture needs a sensible depth key.
